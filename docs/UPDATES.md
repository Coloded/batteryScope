# Официальные обновления BatteryScope

BatteryScope использует официальный [Sparkle 2](https://sparkle-project.org/documentation/) для проверки и установки обновлений. Подписанные DMG публикуются в GitHub Releases; доступные версии перечислены в ленте appcast. Закреплена версия Sparkle 2.10.0 с проверкой SHA-256. Приватный ключ хранится в Keychain в отдельной записи `BatteryScope`; на GitHub публикуется только открытый ключ.

## На другом Mac

1. Скачать `BatteryScope-stable.dmg` из последнего [релиза](https://github.com/Coloded/batteryScope/releases/latest).
2. Скопировать BatteryScope в «Программы» и запустить.
3. Использовать «Проверить обновления…» в меню BatteryScope, меню значка возле часов или в настройках. Автоматическая проверка включена по умолчанию, установка требует подтверждения пользователя.

DMG содержит универсальное приложение arm64 + x86_64 для macOS 13+. Начиная с 0.5.1 для чтения iPhone/iPad встроены универсальные утилиты libimobiledevice со всеми несистемными зависимостями. Установка Homebrew на компьютере пользователя не требуется. В релизе также доступны соответствующие исходники библиотек и скрипт сборки.

Сборки 0.3.x и старше не содержат Sparkle: их нужно один раз вручную заменить на 0.4.0 или новее. Данные SQLite и настройки остаются в профиле пользователя, вне `.app`. Обмен историей между Mac включается отдельно в настройках iCloud приложения.

## Подготовка следующего релиза

1. Увеличить `CFBundleShortVersionString` и числовой `CFBundleVersion` в `Info.plist`.
2. Обновить `updates/release-notes.md`.
3. Выполнить `bash scripts/prepare-release.sh` на Mac с ключом `BatteryScope` в Keychain. Скрипт собирает обе архитектуры, создаёт DMG, подписывает его Sparkle и обновляет appcast.
4. Запустить `bash scripts/test.sh` и `python3 scripts/validate-release.py`.
5. Закоммитить исходники, appcast, DMG и соответствующий архив исходников библиотек из `dist/`.
6. Создать тег `v<версия>` и отправить сначала только тег в origin. Workflow проверит исходники/бандл/подпись и опубликует релиз автоматически.
7. После успешного workflow проверить доступность и контрольные суммы файлов релиза, затем отправить `main`: это переключит канал обновлений на уже доступный установщик.

Архивы сохранены в Git, чтобы GitHub Actions публиковал проверенные и подписанные файлы без повторной сборки. Лента ссылается на конкретный тег релиза, чтобы кэшированная старая подпись не применялась к новому `latest`-архиву. Имя `BatteryScope-stable.dmg` остаётся постоянным для ручного скачивания через `/releases/latest/download/`.

Проверка релиза сверяет манифест исходников, версии и bundle identifier, наличие обеих архитектур, подпись кода, Ed25519-подпись DMG и отклонение изменённого архива. Секретный ключ не нужен GitHub Actions. Не теряйте Keychain: новым ключом нельзя незаметно заменить существующий ключ в установленных приложениях.

## Подписи

Подпись Sparkle подтверждает происхождение обновления. Она не заменяет Apple Developer ID и нотарификацию Gatekeeper. Текущая сборка подписана ad-hoc; сертификата Developer ID на этом Mac не обнаружено. Для нотарифицированной дистрибуции потребуется отдельная настройка сертификата и Apple notary service.

Сборка `.app` хранится во временной папке macOS, чтобы сохранить symlink-структуру Sparkle. На внешний том переносится DMG, а не распакованный framework. После сборки путь приложения выводит `scripts/build.sh`.

## 0.7.0

Обновите BatteryScope на каждом Mac, чтобы новые снимки iCloud содержали краткую конфигурацию и состояние аккумулятора. Старые снимки сохраняются, но отсутствующие в них сведения восстановить нельзя. График удалённого Mac использует сохранённые измерения, локальный график — последние 30 минут текущего запуска.

Предупреждение о ёмкости ниже 80% является оценкой по сообщённым ёмкостям, а не диагнозом. Рекомендации обслуживания macOS показываются отдельно. Повторные уведомления одного уровня подавляются; уведомления требуют разрешения macOS и включённой настройки в BatteryScope.

## 0.7.1

Максимальная ёмкость показывается в пределах 0–100%: на Mac используется значение macOS, при его отсутствии — явно обозначенная оценка по ёмкостям. Полная и проектная ёмкости в мА·ч сохраняются без искусственного ограничения; исходное отношение доступно в подробностях и экспорте. Заряд и остаток заряда отделены от максимальной ёмкости.

Кнопка «Обновить» запускает обмен историей, если он включён. Новые локальные снимки записываются перед обменом; доставка на другой Mac зависит от iCloud. Исправлено расположение выпадающего меню устройств. Sparkle обновлён до 2.10.0, OpenSSL — до 4.0.3, libplist — до 2.8.0.

## Доступ к ключу при автоматическом выпуске

`prepare-release.sh` использует проверенный по SHA-256 инструмент Sparkle из постоянной папки `~/Library/Application Support/BatteryScopeSigning/Sparkle-<версия>/generate_appcast`. Сам ключ остаётся в Связке ключей.

При первом выпуске этим инструментом разблокируйте Mac и Связку ключей «Вход». В запросе доступа `generate_appcast` к записи «Private key for signing Sparkle updates» с учётной записью BatteryScope выберите «Разрешать всегда». Это разрешение конкретному инструменту; доступ всем приложениям включать не нужно. Введите пароль локально в системном окне, если macOS его запросит.

Последующие подписи тем же инструментом выполняются без повторного вопроса при разблокированной Связке ключей. После обновления самого Sparkle macOS может запросить новое подтверждение. Заблокированную Связку ключей скрипт не разблокирует и пароль не сохраняет.

Исправлено выравнивание выбора устройства. График мощности получил линию с заливкой, подписи времени и мощности, даты для нескольких дней и точное значение при наведении. Пропуски данных отображаются разрывами.

## 0.7.3

- Компактный обзор для небольших экранов: питание в общей сетке карточек, экспорт в меню «…», график целиком виден в уменьшенном окне.

Доставка файлов между Mac зависит от iCloud. История и настройки сохраняются. Apple Silicon и Intel, macOS 13+.
