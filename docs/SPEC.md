# BatteryScope — функциональное исследование и ТЗ

Дата: 8 сентября 2026. Уточнение пользователя: отдельные приложения для iOS не нужны; macOS-приложение должно читать подключённые устройства Apple.

## Референс

Изучены публичное описание coconutBattery 4.3, разделы Plus/FAQ и официальные изображения интерфейса. Это анализ публично заявленных возможностей, а не результаты испытаний установленной платной версии. Лицензионный код и графические ресурсы не используются.

Заявленный состав функций:

| Блок coconutBattery | Назначение |
|---|---|
| Mac Battery Diagnostic | Диагностика аккумулятора Mac |
| iPhone/iPad Battery Diagnostic | Диагностика мобильных устройств |
| Save Battery Health Info | Сохранение истории состояния |
| Menu Bar | Показатели Mac и мобильных устройств в строке меню |
| Wi-Fi | Беспроводное подключение после настройки связи |
| Battery Lifetime Analyzer | Минимумы, максимумы, средние температуры и напряжения; диапазоны заряда/разряда, время работы |
| Advanced Viewer | Дополнительные сведения об устройствах и SSD, включая чтение/запись |
| Notifications | Пороги заряда и оставшегося времени Mac, заряда iPhone/iPad |
| Custom Printing | Отчёты с пользовательскими HTML-шаблонами |

Объём доступных сведений зависит от устройства. Дата выпуска новых устройств может не определяться из-за случайных серийных номеров. coconutBattery Online принимает обезличенные сведения при использовании сервиса. Plus — разовая покупка, пробный режим на 10 запусков. Точное распределение всех пунктов между редакциями требует проверки визуальной таблицы или установленного приложения: текстовая версия страницы не передаёт значки доступности.

Источник: [официальная страница](https://www.coconut-flavour.com/coconutbattery/). [Экран Mac](https://www.coconut-flavour.com/coconutbattery/assets/img/macOS26/macOS26_main_mac_bright.png), [история](https://www.coconut-flavour.com/coconutbattery/assets/img/macOS26/macOS26_main_history_bright.png).

## Этап 1 — Mac

Нативное приложение SwiftUI, macOS 13+, без серверов. Рабочее имя BatteryScope. На настольном Mac корректно показывать отсутствие аккумулятора. Каждая отсутствующая величина — прочерк, а не ноль. Не обещать точное совпадение с процентом Battery Health в настройках Apple: метод расчёта и округление могут различаться.

| Требование | Реализация / ограничение |
|---|---|
| Заряд и состояние питания | IOPowerSources, IOKit; обновление раз в минуту |
| Полная и проектная ёмкость | mAh, с разделением физических величин и процентов |
| Состояние | full / design × 100; не ограничивать сверху искусственно |
| Циклы, температура, напряжение, ток, мощность | Из доступных полей, преобразование единиц |
| Оставшееся время | Системная оценка, без выдуманного прогноза |
| История | JSON, атомарная запись; ежечасные и ручные снимки |
| График и аналитика | История состояния; min/mean/max наблюдаемых величин |
| Строка меню | Заряд, питание, обновление и открытие окна |
| Уведомления | Настраиваемый заряд и время, запрос системного разрешения, подавление повторов |
| Экспорт | CSV с пропусками; HTML-шаблон; печать/PDF |
| Дополнительные сведения | Поля батареи; NVMe/SATA через system_profiler |

Текущая аналитика наблюдений не равна Lifetime Analyzer референса: приложение не знает предысторию до установки. Заводские агрегаты оставлены в исходных полях, где они существуют. Полные счётчики SSD и нормализация заводских агрегатов требуют отдельного исследования оборудования.

Приёмка: собрать .app; выполнить тесты парсинга разных форматов батарей; открыть интерфейс на настоящем Mac; на MacBook сравнить показатели с системными сведениями, проверить изменение при подключении питания, историю после перезапуска, пороговые уведомления и печать многостраничных отчётов. Последние аппаратные проверки не заменяются тестовыми данными.

## Этап 2 — iPhone и iPad (включён в сборку 0.2.0)

### Подключение

1. Найти доверенные устройства через usbmuxd/libimobiledevice, сначала USB.
2. При необходимости показать инструкции: разблокировать экран, подтвердить доверие. Не пытаться обходить код или доверие.
3. Прочитать имя, модель, версию iOS/iPadOS, доступные сведения устройства.
4. Получить базовый заряд через домен `com.apple.mobile.battery`.
5. Запросить диагностику `AppleSmartBattery` / `GasGauge`, проверяя успешность ответа и поддержку полей. Частично доступная диагностика не должна скрывать базовый заряд.
6. Wi-Fi включать отдельно: предварительное USB-сопряжение, настройка Finder, общая сеть. Обнаружение USB и сети объединять по идентификатору, отдавая приоритет USB.

Предполагаемая реализация использует протоколы libimobiledevice. Источники: [проект](https://libimobiledevice.org/), [диагностический инструмент](https://github.com/libimobiledevice/libimobiledevice/blob/master/tools/idevicediagnostics.c), [обнаружение](https://github.com/libimobiledevice/libimobiledevice/blob/master/tools/idevice_id.c), [чтение свойств](https://github.com/libimobiledevice/libimobiledevice/blob/master/tools/ideviceinfo.c). Поддержка конкретных показателей современной iOS должна подтверждаться физическими устройствами.

### Интерфейс и данные

- Боковая панель всех подключённых устройств; соединение USB/Wi-Fi и время последнего успешного чтения.
- Те же карточки батареи, история и экспорт, что у Mac, если данные доступны.
- История отдельно для каждого устройства; старые наблюдения доступны после отключения.
- Отдельные состояния: не доверено, заблокировано, отключено, тайм-аут, диагностика запрещена ОС, зависимость отсутствует.
- Уведомления о заряде по каждому устройству; прекращение опроса после отключения.
- Мобильные показатели в строке меню; выбор основного устройства.
- Не выводить дату производства из случайного серийного номера; неизвестные величины не рассчитывать по догадке.

### Архитектура и приёмка

Вынести провайдеры Mac/USB/сеть за общий интерфейс. Все запросы выполнять вне главного потока с тайм-аутом, отменой и ограничением параллелизма. Предусмотреть адаптер версий libimobiledevice и проверку диагностики по реальным сохранённым ответам без личных идентификаторов. Решение об упаковке зависимостей принять перед распространением; для личного прототипа допустима установка через Homebrew.

Проверить iPhone и iPad на доступных актуальных версиях ОС: доверие/отказ, блокировка, USB hot-plug, переключение Wi-Fi, два устройства одновременно, пропадание сети, отсутствие части полей, перезапуск приложения и раздельная история. До этого совместимость не считать подтверждённой.

## Дальнейшие улучшения Mac

Автозапуск по явному переключателю, выбор интервала опроса/сохранения, фильтры диапазона истории, ротация и удаление истории, нормализованные Lifetime-показатели и SSD SMART при наличии надёжного источника. Эти дополнения не включены в текущий объём. Управление лимитом заряда также не входит в задачу диагностики.

Техническая основа Mac: [Apple IOPowerSources](https://developer.apple.com/documentation/iokit/iopowersources_h). Некоторые поля IORegistry не являются стабильным контрактом Apple; их отсутствие обрабатывается без ошибки всего приложения.

## Реализация 0.2.0: подключённые Apple-устройства

Источники Mac, mobile и Bluetooth работают раздельно, mobile/Bluetooth опрашиваются параллельно вне главного потока. Внутри mobile запросы последовательные, каждый ограничен тайм-аутом; USB имеет приоритет перед Wi-Fi. При недоступности диагностики базовый заряд сохраняется. При отсутствии доверия устройство остаётся видимым с инструкцией, вместо исчезновения из списка.

Bluetooth: system_profiler выдаёт подключённые и ранее известные аксессуары, IOKit дополняет заряд Magic-устройств по совпадающему Bluetooth-адресу. Для AirPods отображаются отдельные значения наушников/футляра, если macOS их сообщает. Отсутствующий общий заряд не вычисляется искусственно. Отключённые устройства имеют отдельное состояние; возраст кэша неизвестен. Для подключённых аксессуаров данные также зависят от частоты обновления самой macOS.

История отдельно по стабильному идентификатору устройства, с обратной совместимостью JSON 0.1.0. Поля компонентов включены в экспорт. Кэш отключённых аксессуаров не записывается и не порождает уведомления.

Подтверждено на оборудовании: iPhone18,2 / iOS 26.6.1 по USB, Magic Keyboard и Magic Trackpad. Телефон виден также в сетевом обнаружении; отдельная сессия без USB ещё не проверена. Кэш отключённых AirPods обнаружен; свежие показания подключённых AirPods пока не проверены. iPad/iPod touch реализованы общим протоколом, но требуют проверки на физических устройствах.

Не обещаем универсальную поддержку батарей Apple Watch, Pencil, AirTag, HomePod, Vision Pro или удалённых Mac. Для них требуется отдельный доступный источник и физическая проверка. Apple TV может обнаруживаться при поддерживаемом сопряжении, но не имеет встроенного аккумулятора; физически не проверен.

## Версия 0.3.0 — SQLite, установка, иконка, характеристики

История перенесена в SQLite: devices, samples, technical, metadata, индексы по устройству/дате, WAL, транзакции и подготовленные запросы. JSON 0.1/0.2 импортируется однократно без удаления оригинала. Повторный импорт исключён маркером и уникальным UUID снимка. Это заменяет прежнее требование хранить историю только в JSON.

Собственная bitmap-иконка с бирюзовой батареей и пульсом, ICNS для macOS. Приложение установлено в /Applications, имеет пункт в верхней панели и продолжает работать при закрытии окна. Завершение — отдельное действие. Автозапуск при входе остаётся будущим улучшением.

Отдельный раздел характеристик показывает все полученные технические поля с поиском и экспортом. Mac: system_profiler аппаратной платформы, ПО, RAM, графики/экранов, NVMe/SATA, USB/Thunderbolt, аудио и питания. iPhone/iPad: аппаратные свойства lockdown, доступные домены накопителя, сведения батареи. Аксессуары: Bluetooth/прошивки/HID. Непредоставленные аппаратные характеристики не выдумываются. Снимок сохраняется в technical отдельно для каждого устройства; пользователю видна дата чтения.
